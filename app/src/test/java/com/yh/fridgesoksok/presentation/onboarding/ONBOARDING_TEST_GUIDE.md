# Onboarding 화면 테스트 가이드

온보딩 화면은 네트워크, 데이터베이스, Context 등 여러 외부 의존성을 가지고 있어 단위 테스트보다는 **수동 테스트** 또는 **Instrumented 테스트**가 더 적합합니다.

## 테스트해야 할 시나리오

### 1. 정상 온보딩 프로세스
**목적**: 모든 단계가 정상적으로 완료되는지 확인

**사전 조건**:
- 유효한 사용자 토큰이 로컬에 저장되어 있음
- 서버가 정상 작동 중
- 네트워크 연결 정상

**테스트 단계**:
1. 앱 실행
2. 온보딩 화면 표시 확인
3. "앱 초기화 중..." 메시지 확인
4. "로그인 확인 중..." 메시지로 전환 확인
5. 홈 화면으로 자동 이동 확인

**예상 결과**:
- 2-3초 내에 홈 화면으로 이동
- 에러 없이 완료

---

### 2. 서버 연결 실패
**목적**: 서버에 연결할 수 없을 때 적절한 에러 처리 확인

**사전 조건**:
- 네트워크 연결 끊김 또는 서버 다운
- 유효한 사용자 토큰 존재

**테스트 단계**:
1. 비행기 모드 활성화 또는 Wi-Fi/모바일 데이터 끄기
2. 앱 실행
3. "서버 연결에 실패하였습니다" 다이얼로그 확인
4. "재시도" 버튼 클릭
5. 여전히 실패하는지 확인
6. "종료" 버튼으로 앱 종료 가능한지 확인

**예상 결과**:
- 다이얼로그가 명확하게 표시됨
- 재시도 기능 작동
- 종료 버튼으로 앱 종료 가능

---

### 3. 토큰 만료
**목적**: 저장된 토큰이 무효할 때 로그인 화면으로 이동 확인

**사전 조건**:
- 만료된 토큰이 로컬에 저장되어 있음
- 서버 정상 작동

**테스트 단계**:
1. 앱 실행
2. 온보딩 진행 확인
3. 로그인 화면으로 자동 이동 확인

**예상 결과**:
- 에러 없이 로그인 화면으로 이동
- 사용자가 다시 로그인 가능

---

### 4. 저장된 토큰 없음
**목적**: 신규 설치 또는 로그아웃 후 상태 확인

**사전 조건**:
- 로컬에 저장된 사용자 토큰 없음

**테스트 단계**:
1. 앱 데이터 삭제 또는 새로 설치
2. 앱 실행
3. 로그인 화면으로 바로 이동 확인

**예상 결과**:
- 온보딩 단계를 건너뛰고 즉시 로그인 화면으로 이동

---

### 5. FCM 토큰 동기화 실패
**목적**: FCM 실패해도 앱 사용 가능한지 확인

**사전 조건**:
- 유효한 사용자 토큰
- FCM 토큰 동기화가 실패하도록 설정 (서버 설정 필요)

**테스트 단계**:
1. 앱 실행
2. 온보딩 진행 확인
3. 홈 화면으로 정상 이동 확인

**예상 결과**:
- FCM 실패해도 앱은 정상 작동
- 홈 화면으로 이동
- 로그에 FCM 실패 메시지 기록됨

---

### 6. 로컬 데이터 초기화
**목적**: 검색어 추천용 로컬 데이터가 올바르게 초기화되는지 확인

**사전 조건**:
- 로컬 데이터베이스가 비어있거나 불완전함

**테스트 단계**:
1. 앱 데이터 삭제
2. 앱 실행
3. "앱 초기화 중..." 메시지 확인
4. 초기화 완료 후 음식 검색 기능 테스트
5. 검색어 자동완성이 작동하는지 확인

**예상 결과**:
- 초기화가 백그라운드에서 완료됨
- 검색어 자동완성 정상 작동

---

### 7. 재시도 기능
**목적**: 서버 연결 실패 후 재시도가 올바르게 작동하는지 확인

**사전 조건**:
- 네트워크 연결 불안정

**테스트 단계**:
1. 비행기 모드로 앱 실행
2. "서버 연결 실패" 다이얼로그 확인
3. 네트워크 다시 연결
4. "재시도" 버튼 클릭
5. 온보딩 재진행 확인
6. 홈 화면으로 이동 확인

**예상 결과**:
- 재시도 시 온보딩 프로세스 처음부터 다시 시작
- 네트워크 복구 후 정상 완료

## 로그 확인 방법

온보딩 과정의 각 단계는 로그로 기록됩니다:

```bash
# Logcat 필터링
adb logcat | grep -E "Onboarding|AppInitializer"
```

### 주요 로그 메시지

#### 정상 온보딩:
```
I/Onboarding: 온보딩 시작
D/Onboarding: 서버 상태 정상
D/Onboarding: 리프레시 토큰 유효
D/Onboarding: 토큰 재발급 성공
D/Onboarding: 기본 냉장고 ID: xxx
D/Onboarding: 사용자 정보 저장 완료
D/Onboarding: API 사용량 정보 조회 완료
D/Onboarding: API 사용량 정보 저장 완료
D/Onboarding: FCM 토큰 동기화 완료
I/Onboarding: 온보딩 완료
```

#### 로컬 데이터 초기화:
```
I/AppInitializer: 로컬 데이터 초기화 시작
D/AppInitializer: DB 데이터 수: 0, CSV 데이터 수: 450, 차이: 450
I/AppInitializer: 데이터 차이가 크므로 재초기화 수행
D/AppInitializer: CSV에서 450개 항목 파싱 완료
I/AppInitializer: 로컬 데이터 초기화 완료
```

#### 에러 발생:
```
E/Onboarding: 서버 연결 실패: Connection timeout → 온보딩 실패
E/Onboarding: 리프레시 토큰 무효 → 온보딩 실패
```

## 성능 벤치마크

| 시나리오 | 예상 소요 시간 |
|---------|--------------|
| 정상 온보딩 (네트워크 양호) | 1-2초 |
| 정상 온보딩 (네트워크 느림) | 3-5초 |

| 서버 연결 실패 (타임아웃) | 10-15초 |

## 자동화 테스트 가능성

### Espresso UI 테스트 예시

```kotlin
@Test
fun onboarding_withValidToken_navigatesToHome() {
    // Given: 유효한 토큰 저장
    // When: 앱 실행
    // Then: 홈 화면 표시 확인
}

@Test
fun onboarding_withServerFailure_showsRetryDialog() {
    // Given: 서버 연결 불가 상태
    // When: 앱 실행
    // Then: "재시도" 다이얼로그 확인
}
```

### 참고사항

- 실제 네트워크를 사용하는 테스트는 불안정할 수 있음
- Mock 서버를 사용하는 것을 권장
- OkHttp Interceptor로 네트워크 상태 시뮬레이션 가능

## 디버깅 팁

### 1. 온보딩이 너무 빠름
- Logger 레벨을 DEBUG로 설정하여 각 단계 확인
- 필요시 각 단계에 delay 추가 (디버그 빌드에만)

### 2. 특정 단계에서 멈춤
- Logcat에서 마지막 성공한 단계 확인
- 해당 UseCase의 Repository 구현 확인
- 네트워크 요청 타임아웃 설정 확인

### 3. 재시도가 작동하지 않음
- `retryOnboarding()` 함수가 상태를 초기화하는지 확인
- LaunchedEffect의 의존성 배열 확인
